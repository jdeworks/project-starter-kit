# project-starter-kit

A structured foundation for AI-assisted software projects. Designed so AI agents (Claude Code,
OpenCode, Cursor, and others) produce maintainable code from day one — not just working code.

## The problem this solves

AI agents are excellent at building fast. They're poor at keeping code healthy as it grows —
file complexity creeps up, dead code accumulates, context is lost between sessions, and tests
get skipped. This kit gives every project a quality layer from the start: enforced health
checks, structured change tracking, multi-tier testing, and lifecycle hooks that keep agents
honest across sessions.

---

## Quick start

Navigate to your project folder and run:

```bash
bash <(curl -sL https://raw.githubusercontent.com/jdeworks/project-starter-kit/dev/cli/get.sh)
```

The script walks you through picking a variant and starter template. You can also pass them directly:

```bash
bash <(curl -sL https://raw.githubusercontent.com/jdeworks/project-starter-kit/dev/cli/get.sh) game-dev --starter pixijs
```

This downloads only the files you need (no git history, no other variants) into the current directory.
Then open your AI agent and say:

> Read AGENTS.md and tell me what mode we're in and what commands are available.

Each variant's README has the exact command — browse to any variant below and copy it.

## How it works

The kit has four layers: **base** (shared quality infrastructure), **variant** (project-type
guidance), **starters** (working hello-world code per engine/framework), and **CLI** (tooling
to compose them). When you run `compose.sh`, it merges base + variant + starter into your
project without overwriting existing files.

```
project-starter-kit/
│
├── base/                        # Shared quality layer (every project gets this)
│   ├── AGENTS.md                # Agent entry point — mode, commands, rules, doc table
│   ├── CLAUDE.md                # Redirects to AGENTS.md
│   ├── CHANGES.md               # Append-only change log template
│   ├── SESSION_SUMMARY.md       # Session handoff template (auto-generated by hooks)
│   ├── Makefile                 # Task runner: make check, make test, make health
│   ├── .claude/                 # Claude Code hooks + settings
│   │   ├── settings.json        # Hook wiring (PostToolUse, PreCompact, Stop, SessionStart)
│   │   └── hooks/               # 5 lifecycle scripts
│   ├── .opencode/               # OpenCode hooks + commands
│   ├── .cursor/rules/           # Cursor redirect to AGENTS.md
│   ├── .windsurf/rules/         # Windsurf redirect to AGENTS.md
│   ├── .github/                 # Copilot instructions
│   ├── scripts/                 # health-check.sh, analyze-changes.sh
│   ├── stacks/                  # Stack-specific Makefile + .gitignore per language
│   │   ├── node/                # Node.js (default)
│   │   ├── go/                  # Go
│   │   ├── python/              # Python
│   │   ├── rust/                # Rust
│   │   └── dotnet/              # C# / .NET
│   └── .kit/                    # Reference docs (read on demand, not upfront)
│       ├── code-health.md       # File size limits, complexity, dead code
│       ├── testing.md           # Three-tier test strategy
│       ├── llm-testing.md       # Testing LLM integrations
│       ├── changelog-protocol.md # CHANGES.md format and rules
│       ├── context-management.md # Context compression, session handoff
│       ├── research-planning.md  # Feature specs, architecture decisions
│       ├── git-and-github.md    # Commits, pre-commit hooks, PRs, branching
│       ├── architecture.md      # How this kit is structured (for contributors)
│       ├── bring-your-own-stack.md # Adapting the kit to unlisted frameworks
│       └── modules/
│           ├── full.md          # Full mode: all enforcement active
│           └── lean.md          # Lean mode: reduced enforcement
│
├── cli/                         # CLI tooling
│   ├── init.sh                  # Create new project (git init + compose)
│   ├── compose.sh               # Copy base + variant into target dir
│   ├── migrate.sh               # Analyze existing repo, write MIGRATION.md
│   ├── upgrade.sh               # Upgrade lean → full mode
│   ├── status.sh                # Show variant status and doc counts
│   ├── validate.sh              # Verify doc references + hook smoke tests
│   ├── test.sh                  # Run CLI integration tests (20 tests)
│   ├── bundle.sh                # Generate bundle.xml for online AI agents
│   └── help.sh                  # Unified help
│
└── <variants>/                  # Project-type guidance (pick one)
    ├── AGENTS.md                # Extends base with variant-specific rules + docs
    ├── .kit/                    # Variant-specific reference docs
    │   └── stack-choice.md      # Framework comparison + mapping table
    └── starters/                # Working hello-world per engine/framework
        ├── starters.json        # Manifest (CLI + LLM discovery)
        └── <engine>/            # e.g. pixijs/, phaser/, hono/, expo/
            ├── package.json     # Ready to npm install && npm run dev
            ├── src/             # Working starter code
            └── tests/           # At least 1 passing test
```

## Variants

Each variant adds project-type-specific rules, docs, and framework guidance on top of the
base layer. **Every variant is framework-agnostic** — the rules apply regardless of your stack.
Example commands use a recommended framework; see each variant's `.kit/stack-choice.md` for
alternatives.

| Variant | What it's for | Example stack | Docs |
|---------|--------------|---------------|------|
| [`website`](website/) | Static site, SSR, blog, portfolio | Vite + vanilla JS | [10 docs](website/.kit/) |
| [`api-service`](api-service/) | Backend API (REST or GraphQL) | Node.js + Hono | [6 docs](api-service/.kit/) |
| [`saas`](saas/) | SaaS with auth, billing, multi-tenancy | Next.js + Stripe | [6 docs](saas/.kit/) |
| [`monorepo`](monorepo/) | Frontend + backend + shared packages | Turborepo | [5 docs](monorepo/.kit/) |
| [`cli-tool`](cli-tool/) | Command-line tool | Node.js + Commander | [5 docs](cli-tool/.kit/) |
| [`mcp-server`](mcp-server/) | Model Context Protocol server | TypeScript MCP SDK | [5 docs](mcp-server/.kit/) |
| [`mobile-app`](mobile-app/) | iOS + Android app | React Native + Expo | [7 docs](mobile-app/.kit/) |
| [`game-dev`](game-dev/) | Browser-native game | Phaser 3 | [5 docs](game-dev/.kit/) |
| [`desktop-app/cross-platform`](desktop-app/cross-platform/) | Desktop app (Win/Mac/Linux) | Tauri 2 | [5 docs](desktop-app/cross-platform/.kit/) |
| [`desktop-app/native`](desktop-app/native/) | Native desktop app | C# / .NET MAUI | [4 docs](desktop-app/native/.kit/) |

## Modes

| Mode | What's enforced | When to use |
|------|----------------|-------------|
| **full** | 3 test tiers, all hooks, CHANGES.md required, `make check` mandatory | Features going to production |
| **lean** | Feature tests only, reduced hooks, CHANGES.md optional | Spikes, prototypes, early MVP |

Start lean, upgrade anytime:
```bash
bash cli/upgrade.sh
```

Update to the latest starter-kit version:
```bash
bash <(curl -sL https://raw.githubusercontent.com/jdeworks/project-starter-kit/dev/cli/update.sh)
```

## CLI reference

All commands support `--help`. Run `bash cli/help.sh` for the full list.

| Command | What it does |
|---------|-------------|
| `bash cli/init.sh` | Create a new project (git init + compose in one step) |
| `bash cli/compose.sh` | Copy base + variant into an existing directory |
| `bash cli/migrate.sh` | Analyze an existing repo and generate a migration guide |
| `bash cli/upgrade.sh` | Upgrade lean mode to full mode |
| `bash cli/update.sh` | Update starter-kit infrastructure to latest version |
| `bash cli/status.sh` | Show variant status, doc counts, self-hosting health |
| `bash cli/validate.sh` | Verify all doc references exist, run hook smoke tests |
| `bash cli/test.sh` | Run 26 CLI integration tests |
| `bash cli/bundle.sh` | Generate `bundle.xml` for online AI agents (ChatGPT, Gemini) |
| `bash cli/help.sh` | Show all commands, variants, and examples |

**Common flags:**
- `--help`, `-h` — show usage for any command
- `--dry-run` — preview what would happen without writing files (compose, migrate)
- `--yes`, `-y` — skip confirmation prompt (compose)
- `--variant <name>` — which variant to use
- `--starter <id>` — which starter template (e.g. pixijs, hono, expo)
- `--mode full|lean` — enforcement level

## Agent support

| Agent | Entry point | Hooks |
|-------|------------|-------|
| Claude Code | `AGENTS.md` + `CLAUDE.md` | Full — `.claude/hooks/` (4 lifecycle events) |
| OpenCode | `AGENTS.md` | Partial — `.opencode/hooks/` (session start/end) |
| Cursor | `AGENTS.md` + `.cursor/rules/` | None — use `HOOKS.md` as manual checklist |
| Windsurf | `AGENTS.md` + `.windsurf/rules/` | None — use `HOOKS.md` as manual checklist |
| Copilot | `.github/copilot-instructions.md` | None — use `HOOKS.md` as manual checklist |
| Online (ChatGPT, Gemini) | `bundle.xml` via `bash cli/bundle.sh` | None — use `HOOKS.md` |

## What you get after composing

After running `compose.sh` or `init.sh` with a starter, your project has:

```
your-project/
├── AGENTS.md              # Your agent reads this first
├── CLAUDE.md              # Redirects to AGENTS.md
├── CHANGES.md             # You append to this at session end
├── Makefile               # make check, make test, make health, make dev
├── package.json           # From starter — ready to npm install
├── src/                   # From starter — working hello world
├── tests/                 # From starter — at least 1 passing test
├── .claude/               # Claude Code hooks + settings
├── scripts/               # health-check.sh, analyze-changes.sh
├── .kit/                  # Kit reference docs (hidden — won't conflict with docs/)
│   ├── code-health.md
│   ├── testing.md
│   ├── stack-choice.md    # From your variant
│   └── ...
└── ...                    # Agent configs, session files, etc.

# docs/ is NOT used — it stays free for GitHub Pages or your own documentation.

```

**Key commands:**
```bash
make dev        # Start dev server
make check      # Full quality pipeline (format + lint + types + deadcode + tests + health)
make test       # Run tests only
make health     # Architecture health check (file sizes, LOC budget, console.log)
make help       # List all targets
```

## Relationship to think-tank

[think-tank](https://github.com/jdeworks/think-tank) is a companion planning tool. When a
feature is complex enough to need architecture decisions before implementation, use think-tank
to iron out the specifics, then bring the output back as a spec in `.kit/features/`. The
`.kit/research-planning.md` doc in every variant explains when and how to do this.
